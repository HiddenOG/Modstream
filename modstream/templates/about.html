Architecture

Stateless FastAPI nodes serve pages, a versioned JSON API, Server-Sent Events and WebSockets. Moderation runs on two paths: a synchronous one for instant checks, where concurrent requests are micro-batched into shared model passes, and an asynchronous one for high-volume streams, where messages go through a Redis Streams queue to a worker pool that scales independently.

  • Capped, resumable event log

  • Postgres (SQLAlchemy async)
  • Idempotent bulk inserts
  • Redis atomic counters
  • Prometheus + Grafana
  • Liveness / readiness probes

Measured on one laptop: 7,772 msg/s across 2,000 concurrent streams with zero errors and p99 165 ms (rules-only mode; see loadtest/RESULTS.md).

Detection pipeline

  1. Normalization. A 1:1 character translation undoes common evasions (1d10t → idiot, $tup1d → stupid) without shifting offsets, so matches can be highlighted in the original text.
  2. Rule layer. One compiled pattern over a curated lexicon with three tiers. Strong terms (slurs, explicit threats, self-harm encouragement) flag on their own. Contextual insults ("stupid", "loser") go to review, and are flagged when aimed at a person ("you're so stupid"). Mild profanity is allowed unless it targets someone ("fuck you", "your mom is a..."). Disguises (stretched, masked and spaced letters, known misspellings) are undone first, and a pattern catches threats such as "I'm going to find you and hurt you".
  3. Model layer. Detoxify unbiased (a RoBERTa transformer trained on Civil Comments to reduce false positives on identity mentions; engine here: {{ engine }}). Only its insult, threat, identity-attack and severe-toxicity scores count; its "toxicity" and "obscene" scores mostly mean "contains swearing". It acts as triage: it can send a message to human review but never flags alone. It sits behind a Scorer protocol, loads in a background thread, and concurrent requests share one forward pass. When the model isn't installed, the rules run alone.
  4. Policy. Signals combine into a verdict, a 0–1 risk score, unified categories and human-readable reasons.

Verdict policy

VerdictWhenPlatform action
FlaggedA strong term (slur, threat, self-harm encouragement), or an insult or swear word aimed at a person or stacked with another insultNudge author; blur behind content warning
Needs reviewA context-dependent term alone, or the model scores an insult, threat or identity attack ≥ 0.40Nudge author; label for human review
SafeNo signals, or swearing not aimed at anyonePublish normally

The model never flags on its own. On the evaluation set, letting it flag raised false alarms from 5.6% to 9.7–31.9% (friendly banter, people speaking out against bullying, and identity mentions such as "I'm a proud gay man"). As a triage signal it sends more harmful content to review without adding false alarms. The review threshold is set with MODSTREAM_REVIEW_THRESHOLD.

API reference

All endpoints live under /api/v1 and return JSON; interactive OpenAPI docs are at /docs, and Prometheus metrics at /metrics. Errors follow one shape: {"error": {"code", "message", "field"}}.

POST /messagesEnqueue up to 1,000 stream messages for the worker pool (202 Accepted)

WS /wsBidirectional frames: analyze, publish, subscribe, ping

Limitations & ethics

  • Context is hard. Sarcasm, reclaimed slurs, quotes and news reporting are frequent false positives. That's why ambiguous content goes to review instead of being removed automatically.
  • Known model bias. Toxicity models trained on Jigsaw data over-flag mentions of some identity groups. Purely religious vocabulary is deliberately left out of the lexicon for the same reason.
  • English-first. The model and lexicon target English; a few Nigerian Pidgin insults are included in the rules.
  • Privacy. Analyzer and chat text is never persisted. Only verdict metadata is logged for statistics.

Run it locally

# Full stack: API, workers, Redis, Postgres, Prometheus, Grafana
docker compose up --build
docker compose up --scale worker=4

# Zero infrastructure (in-memory broker, SQLite, rules only)
pip install -r requirements-dev.txt
MODSTREAM_SCORER=none python -m modstream api

# Tests and a 1,000-stream load test
pytest
python loadtest/loadgen.py analyze --streams 1000 --rate 5 --procs 3
