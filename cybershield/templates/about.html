Architecture

A Flask application factory with two blueprints: server-rendered pages (which work without JavaScript) and a versioned JSON API that the progressively enhanced UI calls. Both go through one service layer.

{{ icon("code", "icon-sm") }} Client

  • Jinja templates + ES modules
  • Custom CSS design system
  • EventSource (SSE) live feed
  • Pre-send nudge dialog

{{ icon("zap", "icon-sm") }} Service

  • pages / api blueprints
  • Validation & upload sniffing
  • Detector (rules + model)
  • LRU result cache

{{ icon("database", "icon-sm") }} Data

  • SQLite in WAL mode
  • Event outbox → SSE stream
  • Metadata-only scan log
  • Uploads outside static/

Detection pipeline

  1. Normalization. A 1:1 character translation undoes common evasions (1d10t → idiot, $tup1d → stupid) without shifting offsets, so matches can be highlighted in the original text.
  2. Rule layer. Word-boundary regexes over a curated, tiered lexicon. Strong terms (slurs, explicit threats, self-harm encouragement) flag on their own. Contextual terms ("stupid", "bomb", names of extremist groups) only send content to review unless the model agrees.
  3. Model layer. {{ engine }}, a BERT model fine-tuned on the Jigsaw toxic comment dataset, scores toxicity, severe toxicity, obscenity, threats, insults and identity attacks. The model sits behind a Scorer protocol, so it can be swapped or mocked in tests. It loads lazily in a background thread, and batch requests are scored in a single forward pass.
  4. Policy. Signals combine into a verdict, a 0–1 risk score, unified categories and human-readable reasons.

Verdict policy

VerdictWhenPlatform action
FlaggedStrong term, or model ≥ 0.70, or contextual term + model ≥ 0.40Nudge author; blur behind content warning
Needs reviewContextual term alone, or model between 0.40 and 0.70Nudge author; label for human review
SafeNo signalsPublish normally

Thresholds are configurable via the FLAG_THRESHOLD and REVIEW_THRESHOLD environment variables.

API reference

All endpoints live under /api/v1 and return JSON. Errors follow one shape: {"error": {"code", "message", "field"}}.

EndpointDescription
POST /analyzeAnalyze one text. Body: {"text": "…"}
POST /analyze/batchUp to 32 texts in one model pass. Body: {"texts": [...]}
GET /postsRecent feed posts with comments and analyses
POST /postsCreate a post (JSON or multipart with image)
POST /posts/:id/commentsAdd a comment
POST /posts/:id/reactions{"kind": "like" | "share"}
GET /streamServer-Sent Events of new posts and comments. Resumable via Last-Event-ID
GET /statsAggregate counts, flag rate, latency, categories
GET /healthLiveness, version and model readiness
 
# Analyze a message
curl -s {{ request.host_url }}api/v1/analyze \
  -H "Content-Type: application/json" \
  -d '{"text": "you are such a loser"}'

Limitations & ethics

  • Context is hard. Sarcasm, reclaimed slurs, quotes and news reporting are frequent false positives. That's why ambiguous content goes to review instead of being removed automatically.
  • Known model bias. Toxicity models trained on Jigsaw data over-flag mentions of some identity groups. Purely religious vocabulary is deliberately left out of the lexicon for the same reason.
  • English-first. The model and lexicon target English; a few Nigerian Pidgin insults are included in the rules.
  • Privacy. Analyzer and chat text is never persisted. Only verdict metadata is logged for statistics.

Run it locally

# Full stack with the ML model
docker compose up --build

# Or with Python 3.10+
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python app.py

# Lightweight dev mode (rules only, no PyTorch download)
pip install -r requirements-dev.txt
CYBERSHIELD_SCORER=none python app.py
pytest
